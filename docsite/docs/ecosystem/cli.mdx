# Komodo CLI

The Komodo CLI, `km`, can be used to:

- Quickly run executions and update resources.
- Manage variables from scripts.
- Reset user passwords and elevate users to Super Admin.
- Perform database backup, restore, and copy.
- Open interactive host and container terminal sessions.
- Run one-shot remote terminal commands.

The Komodo Core image comes packaged with the Komodo CLI and is available inside a running Core container with `docker exec -it komodo-core km ...`.
This lets the CLI inherit Core-side configuration, which is especially useful for database workflows like `km db backup -y`.

## This Fork

This repository ships a CLI surface that differs slightly from upstream Komodo v2.

It keeps these fork-specific commands:

- `stack`
- `procedure`
- `sync`
- `variable`

It also exposes terminal actions as:

- `km ssh host ...`
- `km ssh container ...`
- `km exec host ... -x '...'`
- `km exec container ... -x '...'`
- `km attach ...`

There is no public top-level `terminal` command in this fork.
Internally, these commands still use the upstream v2 terminal API with `target` + `init`.

Secret variable values are masked by default. Set `KM_SHOW_SECRETS=true` or `KM_SHOW_SECRETS=1` only when you intentionally want them displayed.

## Examples

- `km --help`
- `km list terminals`
- `km execute deploy-stack my-stack -y`
- `km variable list`
- `km ssh host my-server`
- `km exec host my-server -x 'uname -a'`
- `km exec container nginx --server my-server -x 'printenv'`
- `km attach nginx --server my-server`
- `km database backup -y`
- `km update build my-build "version=2.0.0&branch=release"`
- `km set user mbecks super-admin true`

## Install

There are binaries available for Linux (`x86_64` / `aarch64`), macOS (Apple silicon), and a distroless image at `ghcr.io/moghtech/komodo-cli`.

### Linux

Install system-wide to `/usr/local/bin/km`:

```bash
curl -sSL https://raw.githubusercontent.com/moghtech/komodo/main/scripts/install-cli.py | python3
```

Install for a single user to `${HOME}/.local/bin/km`:

```bash
curl -sSL https://raw.githubusercontent.com/moghtech/komodo/main/scripts/install-cli.py | python3 - --user
```

### MacOS (Homebrew)

```bash
brew tap moghtech/komodo && brew install km
```

### Container

```bash
alias km='docker run --rm -v $HOME/.config/komodo:/config ghcr.io/moghtech/komodo-cli km'
km config
```

## Configure

The CLI loads configuration from files, CLI arguments, and environment variables. CLI arguments take precedence.

Use `km config` to inspect the resolved configuration.

### File Detection

When run, the CLI scans the current working directory and `${HOME}/.config/komodo` for files matching `*komodo.cli*.*`.
Files loaded later override conflicting fields from files loaded earlier.

Override the default search paths with `km -c /path/to/base.toml -c ./overrides ...`.

You can also include additional locations by creating a `.kminclude` file in one of the configured directories:

```
# Supports comments

./.komodo
/etc/komodo/komodo.cli.toml
```

Wildcards are not supported inside `.kminclude`.

### Profiles

You can configure multiple profiles in the CLI config and select them with `km -p <profile> ...`.
This is useful for switching between multiple Komodo cores or different database backup and restore settings.

To avoid passing `-p` every time, set `default_profile` at the top level of the config file.
Shared defaults can also be defined at the top level.

### Example File

The configuration can also be passed as YAML or JSON.
You can use it-tools to convert the TOML example:

- YAML: https://it-tools.tech/toml-to-yaml
- JSON: https://it-tools.tech/toml-to-json

Quick download to `./komodo/komodo.cli.toml`:

```bash
wget -P komodo https://raw.githubusercontent.com/moghtech/komodo/main/config/komodo.cli.toml
```
